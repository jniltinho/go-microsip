# Go migration, M5: the parity gate as it stands (task 7.4)

**Update of the same day.** The owner decided every difference and gap this receipt lists, each as recommended in [the decision list](../migration/parity-decisions.md); the matrix now has 26 rows proven, 22 accepted differences, 2 dropped, 73 partial, 15 with nothing and 2 differences that wait for the SBOM. The sections below are the audit as it was written, before the decisions.

Change `openspec/changes/migrate-to-go-wails`, task 7.4. **The gate is not passed and nothing here is the owner's sign-off.** This receipt records a complete audit of the parity matrix against the tree of the commit it is committed with, so that what the gate still needs is on one page: evidence to produce, behavior that go-microsip does not have, and differences that are the owner's to accept or refuse.

## How the audit was made

Every row of part A of [`docs/migration/parity-matrix.md`](../migration/parity-matrix.md) (the 57 requirements and 83 scenarios of the Rust-era specs at `v0.1.0-rc.3`) was read against the text of its requirement, clause by clause, and against what exists now: the tests, the lab scenarios and their report of 2026-11-12, the window walkthrough of the AppImage, the VM logs, the receipts of M1 to M5. Four read-only passes, one per area, wrote a status and its evidence for each row; every test name and every link they cite was then checked to exist, and the result replaced the matrix's status and evidence columns. Nothing was run again for the audit: a status rests on recorded runs. The rule was strict: a clause that no named test or recorded run shows is not shown.

The audit found one gap that was closed at once: no test presented an agent's grant after its expiry (`TestAnExpiredGrantIsNotActive`).

## What the gate still needs

The decisions below are laid out one by one, with options and a recommendation each, in [the decision list](../migration/parity-decisions.md).

### 1. Differences, for the owner to accept or refuse

- **The window is a web page in the system's web view** (design D5), with layout B and seven skins instead of the MicroSIP-like native window and its two themes: A93, A94, A131, A132, A136, A137. Icons are the page's own line drawings, not a reviewed icon font: A134, A135. Screens are checked by audits that fail a run, not against approved baseline captures: A139, A140. Its cost in start-up time and memory is in the [measurements](go-m5-measures-2026-11-12.md).
- **The desktop's GTK 4 and WebKitGTK 6.0 instead of one self-contained executable** (design D11): A103.
- **Windows**: a Unix-domain socket instead of a named pipe (A13); one executable, no console one (A16, B3.21); the toolkit's single instance (A36); links registered at the first start, with no opt-in, no removal and no autostart (A42, A44, and A87 on Linux); no MSI, which the owner accepted on 2026-11-11, and a weaker build pinning than the Rust text asks (A27, A28, A29).
- **No `unsafe` rule**: the counterpart is the layering test, which does not forbid the `unsafe` package or Windows system calls outside the platform packages (A50, A51).
- **The reviewer is Codex** and the visual matrix is seven skins (A112).
- **A database that cannot be opened does not stop the window** when a file or the environment supplies the account; only the service refuses (A74; the Rust candidate did the same).
- From the matrix's open points, unchanged: the names and the `GO_MICROSIP_` prefix, Cobra subcommands, three properties of the Rust SRTP adapter, DTMF as seven packets of 100 ms, the backup made with `VACUUM INTO`, the doctor's output, six error codes never used, and no engine trace variable (B7.5).

### 2. Behavior the Rust text requires and go-microsip does not have

Each needs code or the owner's decision to drop it.

- **Audio**: a local test of microphone and speaker without a call (A57, A58); a separate output for ringing (A55); choosing another device during a call, which now applies at the next start (A55, A56); plain RTP is the default when the media is not set, and the warning is a badge on the call screens only (A59).
- **NAT**: no STUN and no keepalive at all (A61, A62).
- **Notifications**: nothing for a missed call, on either system; no flashing taskbar button on Windows (A85, A39, A41); no notice naming the privacy setting when Windows blocks the microphone (A21).
- **Contacts**: CSV import exists in the database layer and is not offered by the window (A79, A80).
- **Settings**: the form does not show which source holds a field (A64, A66, A68).
- **Agent control**: a result older than a day answers `not_found`, never `result_expired` (A9, A10).
- **Distribution**: no SBOM for the Go artifacts (A27, A28, A108, A114); no access list on the Windows directories and grant files (A23, A47, A48).
