# macOS: what could be done over SSH without a desktop session (2026-11-13)

Change `add-macos-universal`, tasks 4.1, 4.7 and 6.1, and a first look for 2.3. Commit `cd4efbe`, built in the image `go-microsip-build:13`. The Mac is the owner's macOS 15.8.1 VM, x86_64, over SSH with a key. Nobody is logged in at its console (its screen shows the login window) and it has a sound output and no input, so nothing here needed a desktop session, a permission or a microphone. The owner, away from the machine, asked for what SSH alone allows; the tasks of this receipt do not depend on the measurements of group 2, which wait for a logged-in session.

## Sound: a first look (2.3, not done)

A macOS-only test (`coreaudio_probe_darwin_test.go`) calls CoreAudio and AudioToolbox from Go through `purego`, with no cgo.

- The device list works: on this Mac, "1 devices: 0 with an input, 1 with an output", which is what the system reports.
- An 8 kHz mono output queue is created, but `AudioQueueStart` fails with -66681 ("cannot start"). The system's own player fails the same way in the same session: `afplay` prints `AudioQueueStart failed (-66681)`. So over SSH, with nobody logged in, macOS starts no audio queue for anyone; this says nothing about the Go path. The test skips on that status.
- The question the probe exists for, whether a callback made on AudioToolbox's thread enters Go on time while the collector runs, is still open. It needs a logged-in desktop session; capture also needs an input device.
