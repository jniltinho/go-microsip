# M3: skins and refinement (2026-11-12)

Change `openspec/changes/migrate-to-go-wails`, section 5. The seven skins, layout B and the AAA refinement were built during M2 on the owner's request and merged then; this receipt records what M3 still needed, and the evidence each task's verification asks for. Nothing here is call evidence beyond the lab window run it names.

## What was added

- **State never by color alone, checked in every skin** (`frontend/scripts/prints.sh`): on the screens of a call state or an error, each label must start the text of an element that holds, directly, an icon in sight (it has a box, is visible and has a shape). Twelve labels in seven skins.
- **The focus ring of every control, as drawn** (`frontend/scripts/focus.js` in `prints.sh`): on eleven screens of each skin, after a key press that makes the browser show keyboard focus, each control in sight that takes focus is focused and must show an outline of at least 2 px at 3:1 against what it is drawn on. The audit names what must be on the screen before and after, and with a dialog or the menu open it audits that layer.
- **Opacity counts**: text, edges, icons and rings are compared as they end up drawn, at the opacity of the element and of everything it is inside of.
- **Controls of the audits**: every run ends with ten faults put in on purpose (a ring taken away on a call and in the menu, a ring on a transparent control, an audit pointed at a screen that is not there, an icon hidden, an icon and a text in a transparent badge, an icon whose stroke is transparent, an icon whose shapes are transparent, for the state check and for the contrast audit) and fails unless each is reported.
- **Offline start of every skin** (`make go-offline-skins`, `build/qa/offline-skins.sh`): the built window in a container started with `--network none`, each skin saved as the setting, the page's own report (`--ui-trace`) naming that skin, the four destinations of the home screen, every face of the skin's font as loaded and none as failed; the built page scanned for anything loaded from outside itself. A start-up check of one screen per skin.
- **`docs/themes.md`**: the seven edits a skin needs and the checks that catch a forgotten one.
- **`doctor` reports an unknown skin** (ui-themes, "Unknown skin in the configuration"): the window already started with System; the report now says so, without the value (`unknown_theme` in JSON).
- **Dark: hover** (the owner's note on the built window): `--btn-hover` was the color of a key at rest.
- **Bundled fonts** (task 5.4; the owner's decision of 2026-11-12: bundle them, good-looking and well defined): `frontend/src/fonts/` with Inter 4.1, DejaVu Sans 2.37, Liberation Sans 2.1.5 and JetBrains Mono 2.304, the unmodified files of the Debian 13 packages `fonts-inter-variable`, `fonts-dejavu-core`, `fonts-liberation` and `fonts-jetbrains-mono`, each with the package's copyright file. Every skin names a bundled family first; the Ubuntu skin draws in Inter (the Ubuntu font is not bundled: its licence and name are Canonical's). `scripts/go-licenses.sh` writes the font licences into the third-party notices.

**How the window was driven.** Task 5.8 names `agent-desktop`. As recorded for task 4.7, the page is not on the accessibility bus that `agent-desktop` reads, so it sees the frame and nothing inside; the window is driven in the lab with `xdotool` (keys and pointer on the X display) and read through `--ui-trace`. The owner accepted that for 4.7; it has not been asked again for 5.8.

**Windows.** The `.exe` is started in each skin and reads back the skin and its font; it is not taken through a call there. The Windows call walkthrough is part of task 6.3 by the owner's decision.

**Task 5.8 is not checked**: its text asks for `agent-desktop` and for a call in every skin on the `.exe`. Whether the evidence above closes it, as the reworded 4.8 did for M2, is the owner's decision.

Found on the way:

- The first version of the skin walkthrough dialed "600600": the number stays in the field after a call, for a redial. Not a defect; the test clears the field as a person would. `engine/redial/1001` and `engine/redial/1201` were added to the lab (three calls one after the other from one registration).
- The window discarded the engine's log, so a failed call left no trace. Its warnings now go to the standard error, and a failed outgoing call is logged with its SIP status.
- `build/vm/check.ps1` ran a one-line desktop command twice (the self-test); fixed.
- On Windows the database never opened: the instance lock was not implemented, and behind it the database's address put the drive where SQLite reads a host. Both fixed (see the M4 receipt); until then the Windows window kept no settings, contacts or history.

## Not covered

- The "Unencrypted (RTP)" badge is not in the screenshot matrix (the mock's account asks for SRTP); the lab window run reads its label in the real window, not its icon in each skin.
- Hover and pressed states are not in the screenshot matrix; their token pairs are held at 7:1 by `themes.test.ts`.
- The offline start draws the home screen of each skin, not every screen.
- The Ubuntu skin draws in Inter like Light and Dark, not in the Ubuntu font: every skin draws first with a bundled family (ui-themes, "Self-contained skins"). Preferring the system's Ubuntu font where it exists would need that requirement changed.
- The fonts are not subset: the binary carries 3.7 MB of font files (24.2 MB before, 27.9 MB after).
- The fonts were looked at in WebKitGTK and in headless Chromium, not in WebView2 on Windows.
