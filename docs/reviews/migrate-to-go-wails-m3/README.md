# Independent review of milestone M3 (Codex)

Each round reviews a sanitized extract made with `git archive` (the changed packages, the page, the checks and the receipts; no font files, pictures or build output, nothing from `base/`, no secrets or personal paths) and the diff since M2 closed, with `codex exec --sandbox read-only --skip-git-repo-check --ephemeral`. A review is not call evidence: the evidence is in [the M3 receipt](../../receipts/go-m3-skins-2026-11-12.md) and [the tray and route receipt](../../receipts/go-tray-and-route-2026-11-12.md). The reviewer builds and runs nothing.

The scope is wider than the skins: the tray, the close button and the local address were added between M2 and M3 and had no review of their own.

## What was done about round 1

| # | Finding | Response |
| --- | --- | --- |
| 1 | A second close within three seconds ended a call without the confirmation, even after Cancel; a frozen page could ignore requests for ever | Fixed. Asking again is never consent: the page that answers (`App.QuitAsked`, sent by the page's transport when the request arrives) is only asked again. When no page listens, or the last request went unanswered for three seconds, the window asks by itself in a native dialog ("The window is not answering. Hang up and quit?", Cancel by default) and only a yes ends a call; without a call it ends at once. `TestLeavingAsksThePageThatListens` closes four times in a row over an answering page and nothing quits. The native dialog itself is not driven by a test. |
| 2 | A second shutdown, refused after the first was taken, cleared the pending quit, so the application stayed open after the engine stopped | Fixed. `App.Shutdown` is serialized and taken once: while one is pending a second is that same shutdown, sends nothing and undoes nothing. The same test asks three times and the application quits once the engine has stopped. The delayed-`Stopped` interleaving is not forced by the test; the serialization removes the window in which the second request could be refused. |
| 3 | The local address was chosen from one resolved address of the registrar while requests follow the name | Fixed for what can be decided here. The address is bound only when every IPv4 address of the registrar is reached from the same one; otherwise the bind is `0.0.0.0` as before the change (`localFor`, tested with a route table of its own: one address, two that agree, two that differ, one without a route, IPv6 beside it, IPv6 only). Not done: the probe is a UDP route lookup also for TCP and TLS accounts, so a host whose routing differs by protocol is not covered; recorded as a limit. |
| 4 | The registrar's route is also offered for audio; a proxy on the loopback would offer 127.0.0.1 | Fixed for the loopback: a route through the loopback binds `0.0.0.0`, as before. Otherwise the softphone offers for audio the address it reaches the registrar from, like softphones without ICE do; choosing a separate audio address needs the far end before the offer exists (ICE or STUN), which is not in this change. Recorded as a limit in the receipt, and the owner's report is described as registration only. |
| 5 | `scale-check.sh` set the page's cached skin but not the mock's saved one, so the 140 checks could all measure one skin | Fixed, and the finding was right: the earlier runs do not show seven skins. The script sets both, and every check requires the skin it names to be the one drawn (`data-theme` and `data-skin`). Run again: see the receipt. |
| 6 | The audits passed with no focus ring and with an invisible state icon | Fixed. `frontend/scripts/focus.js`, run by `prints.sh` on eleven screens of each skin after a real key press, focuses every control in sight and requires a drawn outline of at least 2 px at 3:1 against what it is drawn on. The state check requires an icon in sight (a box, visible, with a shape) beside the label. Each run ends with two controls: a ring taken away and an icon hidden must be reported, or the run fails. |
| 7 | The font test checked file names; the trace reported a family, not each face; four tab names are not the whole screen | Fixed in part. The page's report lists each loaded face (`family weight`) and the faces that failed; the offline check, the lab window walkthrough and the Windows VM require every face of the skin's font and no failure. The offline check is described as a start-up check of one screen per skin. The unit test still checks names only: a font's validity is checked where it is loaded. |
| 8 | A named color (`style="color: navy"`) passed the literal-color test | Fixed. The test knows every CSS color name, in declarations and in arbitrary-value utilities, and checks itself first with fixtures that must and must not be caught. |
| 9 | `doctor` did not report an unknown skin when no account was configured | Fixed. The skin is read whether or not the configuration resolves; tested with a profile that holds a skin and no account. |
| 10 | The window test's "unregistered" saw only the engine's `Stopped`, not the PBX | Fixed for the close button: the same extension is registered again by a third start, which the lab PBX refuses while a contact remains (`max_contacts=1`, `remove_existing=no`). The comment on `unregistered` says what it does not see. An exit when the PBX does not answer belongs to task 6.1. |

Also noted by the report and kept as it is: the skin walkthrough dials and hangs up in each skin without measuring the sound in each (the sound is measured in the two account runs, one of which changes the skin during the call).
