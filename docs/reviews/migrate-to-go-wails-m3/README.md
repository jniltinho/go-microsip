# Independent review of milestone M3 (Codex)

Each round reviews a sanitized extract made with `git archive` (the changed packages, the page, the checks and the receipts; no font files, pictures or build output, nothing from `base/`, no secrets or personal paths) and the diff since M2 closed, with `codex exec --sandbox read-only --skip-git-repo-check --ephemeral`. A review is not call evidence: the evidence is in [the M3 receipt](../../receipts/go-m3-skins-2026-11-12.md) and [the tray and route receipt](../../receipts/go-tray-and-route-2026-11-12.md). The reviewer builds and runs nothing.

The scope is wider than the skins: the tray, the close button and the local address were added between M2 and M3 and had no review of their own.

## What was done about round 1

| # | Finding | Response |
| --- | --- | --- |
| 1 | A second close within three seconds ended a call without the confirmation, even after Cancel; a frozen page could ignore requests for ever | Fixed. Asking again is never consent: the page that answers (`App.QuitAsked`, sent by the page's transport when the request arrives) is only asked again. When no page listens, or the last request went unanswered for three seconds, the window asks by itself in a native dialog ("The window is not answering. Hang up and quit?", Cancel by default) and only a yes ends a call; without a call it ends at once. `TestLeavingAsksThePageThatListens` closes four times in a row over an answering page and nothing quits. The native dialog itself is not driven by a test. |
| 2 | A second shutdown, refused after the first was taken, cleared the pending quit, so the application stayed open after the engine stopped | Fixed. `App.Shutdown` is serialized and taken once: while one is pending a second is that same shutdown, sends nothing and undoes nothing. The same test asks three times and the application quits once the engine has stopped. The delayed-`Stopped` interleaving is not forced by the test; the serialization removes the window in which the second request could be refused. |
| 3 | The local address was chosen from one resolved address of the registrar while requests follow the name | Fixed for what can be decided here. The address is bound only when every IPv4 address of the registrar is reached from the same one; otherwise the bind is `0.0.0.0` as before the change (`localFor`, tested with a route table of its own: one address, two that agree, two that differ, one without a route, IPv6 beside it, IPv6 only). Not done: the probe is a UDP route lookup also for TCP and TLS accounts, so a host whose routing differs by protocol is not covered; recorded as a limit. |
| 4 | The registrar's route is also offered for audio; a proxy on the loopback would offer 127.0.0.1 | Fixed for the loopback: a route through the loopback binds `0.0.0.0`, as before. Otherwise the softphone offers for audio the address it reaches the registrar from, like softphones without ICE do; choosing a separate audio address needs the far end before the offer exists (ICE or STUN), which is not in this change. Recorded as a limit in the receipt, and the owner's report is described as registration only. |
| 5 | `scale-check.sh` set the page's cached skin but not the mock's saved one, so the 140 checks could all measure one skin | Fixed, and the finding was right: the earlier runs do not show seven skins. The script sets both, and every check requires the skin it names to be the one drawn (`data-theme` and `data-skin`). Run again: see the receipt. |
| 6 | The audits passed with no focus ring and with an invisible state icon | Fixed. `frontend/scripts/focus.js`, run by `prints.sh` on eleven screens of each skin after a real key press, focuses every control in sight and requires a drawn outline of at least 2 px at 3:1 against what it is drawn on. The state check requires an icon in sight (a box, visible, with a shape) beside the label. Each run ends with two controls: a ring taken away and an icon hidden must be reported, or the run fails. |
| 7 | The font test checked file names; the trace reported a family, not each face; four tab names are not the whole screen | Fixed in part. The page's report lists each loaded face (`family weight`) and the faces that failed; the offline check, the lab window walkthrough and the Windows VM require every face of the skin's font and no failure. The offline check is described as a start-up check of one screen per skin. The unit test still checks names only: a font's validity is checked where it is loaded. |
| 8 | A named color (`style="color: navy"`) passed the literal-color test | Fixed. The test knows every CSS color name, in declarations and in arbitrary-value utilities, and checks itself first with fixtures that must and must not be caught. |
| 9 | `doctor` did not report an unknown skin when no account was configured | Fixed. The skin is read whether or not the configuration resolves; tested with a profile that holds a skin and no account. |
| 10 | The window test's "unregistered" saw only the engine's `Stopped`, not the PBX | Fixed for the close button: the same extension is registered again by a third start, which the lab PBX refuses while a contact remains (`max_contacts=1`, `remove_existing=no`). The comment on `unregistered` says what it does not see. An exit when the PBX does not answer belongs to task 6.1. |

Also noted by the report and kept as it is: the skin walkthrough dials and hangs up in each skin without measuring the sound in each (the sound is measured in the two account runs, one of which changes the skin during the call).

## What was done about round 2

| # | Finding | Response |
| --- | --- | --- |
| N1 | A quit was still lost when the engine had already ended and its `Stopped` had not arrived: the refused command cleared the wish to quit | Fixed. A command refused because the engine has ended keeps the wish to quit, and the application quits when the engine's events are through, with or without a last `Stopped` (the closed stream is the end). Only a full queue is a refusal. `TestAQuitOutlivesALateStopped` holds the events back: `Stopped` after the request, a stream that closes without it, and a full queue followed by a stop that must not quit. |
| N2 | The window's own question was skipped when its cached state showed no call, which lags behind the engine | Fixed. The window no longer judges whether there is a call: whenever an engine is running and the page cannot be asked, the native dialog asks ("Quit go-microsip? A call in progress will be ended.", Cancel by default) and only a yes ends the engine. Without an engine, or after it stopped, there is nothing to end. `inCall` is gone. |
| N3 | The agreement of the registrar's addresses holds for one DNS answer; a later lookup may give another address | Not changed; recorded as a limit in the receipt. Requests follow the registrar's name, as the PBX expects in the request line; pinning them to the address looked up would need the library to separate the destination from the name. A registrar whose successive DNS answers are reached through different interfaces is bound to the first answer's address. |
| N4 | The focus audit pressed Tab, which closes the menu: "menu" and "settings" audited the home screen | Fixed, and the finding was right (three identical counts of 12). The audit presses Shift, which makes the browser show keyboard focus and changes nothing, names a selector that must be on the screen before and after, and with a dialog or the menu open audits that layer. The menu now counts its 14 items and the settings 26 controls. Two controls were added: a ring taken away in the menu, and an audit pointed at a screen that is not there. |
| N5 | Opacity of what an element is inside of was ignored: a transparent badge or control passed | Fixed. Contrast, ring and state checks use the opacity the element ends up with (its own times that of everything around it) and compare the color as it is drawn over its background. Three controls were added: an icon and a text in a transparent badge, and a ring on a transparent control. The run now has seven controls and fails unless each is reported. |
| N6 | A named color in an SVG attribute, or a declaration over several lines, passed the literal-color test | Fixed. Presentation attributes (plain or bound) are covered, and each file is also scanned as a whole; fixtures for both. |
| N7 | The event forwarder started before the window existed and read it without synchronization | Fixed. The window is created before the phone is opened and before anything forwards events. |
| N8 | The offline check took a failed scan of the built page for a clean one | Fixed. The built page must be there, and a scan that fails is a failure. |
| N9 | The scale check looked at controls horizontally only | Fixed in part. A control outside a scrolling list must also be within the window's height and not under something else (what is at its centre is the control). The receipt describes the check as what it measures; it is not a visual review. |
| N10 | The Ubuntu skin named the system's Ubuntu font before the bundled one, against the requirement of bundled assets only | Fixed. Every skin, Ubuntu included, draws first with a bundled family, and the font test requires it. Using the system's Ubuntu font first would need the requirement changed, which is the owner's decision. |

Claims the report found too strong, corrected in the receipts: the focus audit's coverage (it is what `focus.txt` of the corrected run records), the literal-color test's reach, "only a yes ends a call" (true of the engine's end as a whole since N2), and the packaged run, which is now named with the commit of the artifact it drove.

## What was done about round 3

The report re-graded two of its round-2 findings as minor (the DNS limit of N3, the wider opacity audit of N5) and took the recorded limit of N3 as defensible. From round 3 on the extract also holds work of task 6.1 (links, the bounded stop), reviewed for defects.

| # | Finding | Response |

| 1 | The page quit without a question whenever it knew of no call, and what it knows of calls comes late: a call it had not heard of yet was ended | Fixed in the engine, as the report asked. `Shutdown` can be conditional (`IfIdle`): the actor, which owns the calls, takes it only when there is none and answers. The page's Quit without a question is that conditional command (`App.Quit`); "busy" brings the question, and only the yes sends the unconditional one. `TestAConditionalShutdownIsRefusedDuringACall` asks right after dialing, before any snapshot is read; `TestAnUnaskedQuitIsTheEnginesToDecide` and the page's "quitting during a call asks first" cover the two sides. |

A question on the screen stays the one that is answered: a link that arrives meanwhile is dropped with a notice. Tested with two links and with a link over a pending delete. |

The domain checks the IPv6 text form itself (it uses no library: the layering test refused `net/netip`), with fixtures for too few and too many groups, two compressions, a long group, an IPv4 tail out of range, a zone and a bare IPv4 address. |
