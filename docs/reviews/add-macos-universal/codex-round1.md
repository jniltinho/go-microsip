The overall direction is feasible, but the plan is not approval-ready. It understates several adapter contracts and leaves gaps in privacy testing and release enforcement.

This is a static review, not evidence that anything builds, runs, or carries a call. Below, **change/** means `openspec/changes/add-macos-universal/`.

### CoreAudio verdict and spike criteria

**AudioQueue is a reasonable experimental candidate, not yet a demonstrated fit for this contract.** Apple explicitly supports callbacks on AudioQueue-owned threads when no callback run loop is supplied. That establishes an API mechanism, not Go runtime safety or latency. [Apple AudioQueueNewInput](https://developer.apple.com/documentation/audiotoolbox/audioqueuenewinput(_:_:_:_:_:_:_:))

Task 3.1 needs these explicit failure controls:

- **ABI and lifetime:** correct structure layouts on both architectures; valid callback state through GC; no callbacks accessing disposed queues; repeated open/close and partial-open failure cleanup.
- **Callback resources:** measure the complete callback bridge, not just ring operations. Reuse callback registrations: purego documents a finite callback table whose registrations are not released. [purego callback implementation](https://github.com/ebitengine/purego/blob/v0.11.1/syscall_unix.go)
- **Format and timing:** 44.1/48 kHz and differing input/output rates; mono/stereo conversion; varying callback fragment sizes; sustained drift; bounded queue depth and measured conversational latency.
- **Privacy:** late pre-discard deliveries, including conversion state; no unexpected microphone opening for `OpenOutput`, ringing, or ringback.
- **Concurrency and shutdown:** discard while capture runs, close while callbacks run, device removal, service failure, and recovery without a microphone switch.
- **Measurement validity:** observe actual captured and rendered signals, not merely successful enqueue operations or RTP packet counts.

The five-second stall must mean **the UI/event consumer is stalled while media continues**. Stalling the media consumer itself is a negative control that should fail the timing threshold.

The “shared conformance test” is not currently a ready-made portable harness: the substantial device fixtures are in `pulse_linux_test.go` and `wasapi_windows_test.go`. Shared ring tests do not prove a new backend. A Darwin signal-injection/render-observation fixture is real work.

Finally, the existing loss/gap threshold does not limit constant latency: a consistently delayed call can pass it. Record capture-to-RTP and RTP-to-render delay and agree on a latency ceiling.

### Signing and privacy claim assessment

| Claim | Assessment |
|---|---|
| Go’s internal linker supplies an arm64 ad-hoc signature | **Known.** Go contains the signature-generation machinery. This is not Developer ID signing, notarization, or a sealed application bundle. [Go linker source](https://go.dev/src/cmd/link/internal/ld/macho.go) |
| Joining slices necessarily removes the arm64 signature | **Wrong.** Signatures are per architecture; byte-preserving joining need not remove them. A native Intel inspection can conceal the arm64 result. [Apple TN3126](https://developer.apple.com/documentation/technotes/tn3126-inside-code-signing-hashes) |
| Browser downloads encounter quarantine/Gatekeeper; macOS 15 removed the Control-click bypass | **Known in the documented normal path.** The exact download/extraction/opening behavior still needs task 6.4. Prefer the supported Privacy & Security override; do not recommend globally disabling Gatekeeper. [Apple Sequoia announcement](https://developer.apple.com/news/?id=saqachfa) |
| The unsigned bundle will obtain microphone permission, potentially asking again after updates | **Plausible, must be measured.** The usage declaration is required; initial authorization, responsible-process attribution, and update persistence need packaged-application tests. The plist key alone is not acceptance evidence. [Apple microphone declaration](https://developer.apple.com/documentation/bundleresources/information-property-list/nsmicrophoneusagedescription) |
| Unsigned code necessarily cannot use the local network, or Developer ID automatically resolves every denial | **Wrong as blanket statements.** Identity tracking is signature-sensitive, but launch context and user authorization matter. Terminal/SSH tools receive different treatment from desktop apps. Test the actual bundle from a desktop session. [Apple TN3179](https://developer.apple.com/documentation/technotes/tn3179-understanding-local-network-privacy) |
| Notifications may be unavailable for this unsigned bundle | **Plausible, must be measured.** Do not promise success or universal refusal across versions. Authorization is a separate lifecycle, and the fallback must survive native initialization failure. [Apple notification authorization](https://developer.apple.com/documentation/usernotifications/asking-permission-to-use-notifications) |
| Signing later is merely an additional packaging command | **Wrong if treated that way.** Hardened-runtime recording needs the relevant audio-input entitlement; the signed application needs renewed privacy and functional acceptance. Do not confuse hardened runtime with App Sandbox. [Apple audio-input entitlement](https://developer.apple.com/documentation/bundleresources/entitlements/com.apple.security.device.audio-input) |

**Task 2.8 is directionally correct but should move immediately after minimal bundle creation.** Use clean disposable privacy state and the actual desktop-launch path. An SSH-launched executable or successful hosted-runner command is not equivalent evidence.

### Machines, task ordering, and verifiability

- **Current x86_64 VM:** suitable for structural/headless checks and some desktop checks after owner preparation. Without an input and a signal fixture, it cannot verify two-way capture. A virtual input does not prove real-headset behavior.
- **Hosted runners:** suitable for executing each slice and the window self-test. They are not evidence for real audio, notification interactions, or the user’s first-run privacy experience.
- **Raw cross-built test binaries:** do not automatically inherit the application bundle’s microphone declarations or identity. Specify how privacy-sensitive tests are packaged and launched in the logged-in session. Merely having a logged-in user is insufficient proof of equivalent attribution.
- **A person with each architecture:** remains necessary for the promised real-hardware acceptance. Writing checklist rows does not execute them.

Most requirements have observable outcomes, but the CI architecture exception conflicts with the unconditional “each architecture” SHALL; make that exception explicit in the requirement. Likewise, identify exactly which unverified items are allowed for a pre-release and which block a final release.

Tasks 3.1, 4.2, 4.3, and 6.1 are mini-milestones, not single checks. Split each into fixtures/unit controls and native acceptance. Bring the minimal SSH/desktop test plumbing forward. Each declared milestone should land its tests, documentation, receipt, regression checkpoint, and independent review—not defer all review to 7.3.

During transition, the current release workflow can:

- publish an old complete set without macOS if neither its checksums nor required-file list includes it;
- reject a good local build if CI’s upload copy list omits the new zip;
- reject a set when uploaded files and `SHA256SUMS` disagree.

The design’s atomic-transition rule is therefore important and should become an explicit task dependency with controls.

## 3. Checked and found supported

- The existing core/adapter split is appropriate; no macOS-specific core APIs are necessary.
- Unix file-ownership and `flock` adapters already have build constraints applicable to Darwin.
- Audio already provides bounded rings, counters, speaker-only playback, and a privacy-sensitive discard contract worth reusing.
- Linux and Windows keyrings implement the same `Secrets` port. The application already supplies opaque, randomly generated credential references.
- Direct `/usr/bin/security -i` execution with a pipe can avoid putting the secret in OS-visible argv. The sibling does not invoke a shell. Its default trusted-tool exposure is honestly acknowledged; it is not application-isolated storage.
- Linux control provides concrete security behavior and negative tests to port. Unknown peer PID is supported by the owner contract.
- Shared GUI code already creates the tray menu, hides the window on close where a tray exists, reveals incoming calls, and routes normal quit through confirmation.
- The existing URL parser treats links as data and prevents a supplied SIP host from selecting another signaling server.
- Notifications already have missed-call, removal, and stale-action behavior that the macOS adapter should preserve.
- Release publication already reuses a successful main-branch CI artifact rather than rebuilding it.
- The publication scanner already unpacks **all `.zip` files**. macOS needs coverage controls and inclusion in the uploaded set, not a separate ZIP extraction mechanism.
- The proposal correctly separates preliminary observations from acceptance evidence and does not claim that the uninstalled macOS 26 VM was tested.
